# 会計人プロフィール（Accounting Profile）

公認会計士・税理士から、受験生・監査アシスタント・会計事務所職員・経理／経理補助まで、**会計にかかわる人のためのプロフィールメーカー**です（**資格の有無は問いません**）。「働く人向け」とだけ書くと自分が対象か分からないので、職種を具体的に並べています。49問のLikertと7つの選択操作から、5つの独立したレイヤーで「あなたの会計人としての輪郭」を可視化します。

**ビルド不要の静的サイト**（Vanilla JS + ES Modules）。サーバーを持たず、採点も結果表示もすべてブラウザ内で完結します。

```bash
node scripts/dev-server.mjs
```

→ http://localhost:4173

公開前チェック（依存なし・約130項目）:

```bash
npm test
```

16タイプと画像・静的ページの整合、スコアリングの境界、受験していない人の
完走と再開判定、排他選択、共有URLと OGP の宣言を確認します。
`src/data.js` や `assets/` を触ったら実行してください。

## 結果はサーバーに保存されません

このアプリにはバックエンドがありません。**通常利用では、回答も結果も外部へ送信されません。**
ただし共有操作をしたときだけは、結果が共有先へ渡ります（X の投稿画面に渡す URL、
Instagram の共有シートに渡す画像）。**渡るものはリンクと画像で違います。**
リンクはアーキタイプと Work Style 4軸、それに**性格まで答えた人は修飾語**
（「まわりを立てる」）。画像（正方形カード）にはさらに**性格タグ**（「外向性 高め」）も
描かれています。画面上の表現もこれに合わせてあります。

| 項目 | 扱い |
|---|---|
| 回答内容 | ブラウザ内でのみ保持。送信しない |
| 採点・結果生成 | すべてクライアントサイド |
| 一時保存 | `localStorage` に**回答内容のみ**（この端末内）。中断からの再開と、前回の結果の再表示に使う。結果そのものは保管しない |
| 結果の保管 | **行わない**。結果画面を閉じると同じ結果は再取得できない |
| 共有リンク | `/t/{CODE}/#p=CODE.pct.pct.pct.pct[.m]`。**その URL を直接開く分には**、数値はフラグメントなのでサーバーへ送信されない。含まれるのは Work Style 4軸とアーキタイプ、性格まで答えた人は修飾語の番号のみ。パス（`/t/{CODE}/`）はアーキタイプまでしか示さない。読むときだけ `?p=` も受けるが、**こちらから `?p=` を作ることはしない**（クエリだとサーバーの記録に数値が残るため） |
| 共有操作をしたとき（リンク） | この URL がクエリ文字列の一部として X の投稿画面に渡る（＝ X へ渡る）。含まれるのはアーキタイプ・Work Style 4軸と、性格まで答えた人は**修飾語の番号**（`#p=CODE.pct.pct.pct.pct.m`。語そのものではなく 1〜4 の番号。付かない人は末尾ごと無い＝旧リンクもそのまま読める） |
| 共有操作をしたとき（画像） | Instagram には正方形カードが共有シート経由で渡る。アーキタイプ・Work Style 4軸に加えて、**性格から作った修飾語と性格タグ**が描かれている（`archetypeModifier` / `personalityTags`）。**科目・実務・勉強の回答はどちらにも渡さない** |
| 外部リクエスト | Google Fonts（Shippori Mincho・明朝体のフォールバック）と、ユーザーが押した場合のみ X の共有画面。フォントのリクエストに回答データは含まない |

`localStorage` に置くキーは次の2つだけです。

- `kprofile.v1` — 回答内容（`ans` / `ops` / `page`）。中断時の再開と、トップの「前回の結果をもう一度見る」に使う。トップの「この端末の回答を削除」または結果画面の「もう一度作る」で消去
- `kprofile.autoAdvance` — 自動で次ページへ進むかの設定

### 結果を残せるのは、回答直後のその場だけ

サーバーに保管しない以上、結果を他の端末へ持ち出す手段は **PNG プロフィールシート**
（5レイヤーを1枚にした縦長画像・1080×約2500 @2x）だけです。ブラウザ内で生成し、送信は行いません。

同じ端末に限っては `kprofile.v1` が残っている間、トップの「前回の結果をもう一度見る」で
結果を作り直して再表示できます（結果そのものではなく回答から再計算しています）。

保存ボタンを出すのは**自分の回答から確定した結果を表示しているときだけ**です。アーキタイプ図鑑のプレビューや共有リンクからの復元では表示しません。

> 以前は JSON でも書き出し、それを読み込んで結果を復元できるようにしていましたが、
> 「保存したい人には画像で足りる」という判断で廃止しました（`downloadJson` /
> `parseSavedFile` を削除）。中断からの再開は元々 `localStorage` の下書きが担っており、
> JSON 廃止の影響を受けません。

## 診断モデル

5つのレイヤーは**別系統でスコアリングし、相互に加点しません**。総合点は作らず、適職判定・求人推薦・年収予測・採用評価は行いません。

| # | レイヤー | 内容 | 設問/操作 | 出力 |
|---|---|---|---|---|
| 1 | **Personality** | Big Five（IPIP等の公開心理尺度を参考にした独自和文項目） | 25問（各特性5問） | 5特性の連続スコア 0–100 |
| 2 | **Work Style** | 会計実務の進め方（プロダクト独自4軸） | 16問（各軸4問） | 4軸の連続スコア + アーキタイプ |
| 3 | **Subject DNA** | 試験科目への興味（経験資格で科目リストを切替） | 4操作（S0–S3）※受験していなければ S0 のみ | 上位3科目 + 理由タグ |
| 4 | **Practice DNA** | 実務領域への興味（経験/好き/やりたいを区別・24領域） | 3操作（P1–P3） | 上位4領域 + 理由タグ |
| 5 | **Study Behavior** | 学習行動 | 8問（各1問） | 8指標を3段（いまの学習スタイル／ときどき／これから試せる）に振り分けたタグ |

計 **49問 + 7操作 = 56回答**（18ページ）。ほかに、Work Style の軸が同点になった人にだけ
二択のページが1つ増えます（下記「同点の軸」）。

### 2段構成 — まず16問でアーキタイプ

アーキタイプは **Work Style のみ**から生成します。アーキタイプの決定に使わない
Personality 25問を先に置くと「ちょっとやってみる」の範囲を超えるため、
最初に答えてもらうのは Work Style の16問だけにしています。

| | 内容 | 回答 | ページ |
|---|---|---|---|
| **STEP 1（コア）** | Work Style 16（+ 同点の軸があれば二択） | 16（+0〜4） | 4（4問×4）＋同点があれば1 |
| **STEP 2（任意）** | Personality 25 → Study 8 → Subject/Practice DNA 7操作 | 40 | 14（5問×5 + 4問×2 + 7操作） |

16問を終えると結果画面に入り、動物・アーキタイプ名・キャッチコピー・4軸がそろいます。
そこから先はレイヤーを1つずつ足していく形で、**レイヤーを終えるたびに結果画面へ戻り**、
増えたぶんをその場で見せます（`isLayerEnd()` — `src/scoring.js`）。

誘い文句は「次に足せるもの」で決めます。修飾語（まわりを立てる 等）は Personality
からしか出ないので、性格が未回答のあいだは **「性格を足すと、名前に一言つきます」** が
そのまま続ける理由になります。全体の残り問数は前面に出しません（重く見えるため）。

進捗の分母も STEP 1／STEP 2 で分けており、`16/56` のような未完了表示は出しません。
未回答のレイヤーは結果画面でカードごと表示されないため、途中結果と完全版で
画面を作り分けていません。ページ境界はセクションの切れ目と一致させています
（`LIKERT_SECTIONS` / `pages()` — `src/scoring.js`）。

出題順は `LIKERT_SECTIONS` の並びだけで決まります。`likertItems()` の並び
（= 回答インデックス）は変えていないので、順序を入れ替えても保存済みの回答は
そのまま使えます。中断からの再開は保存した page 番号ではなく回答から求めます
（`firstIncompletePage()`）。

### 対象は資格の有無を問わない

会計士・税理士だけでなく、**監査アシスタント・会計事務所職員・経理補助・受験生**まで
含めています。母集団の大きさもありますが、設計上そもそも無理がありません。

アーキタイプを決める Work Style 16問は「資料の見方」「突合」「段取り」「チェックリスト」
「一人で調べるか相談するか」で、**資格や役職に一切依存しません**。むしろ突合や資料確認は
アシスタント・事務所職員の日常業務です。全員が同じ16問から動物を得るので、
対象を広げても「16タイプ」の比較可能性は保たれます。

調整が要ったのは STEP 2 の2レイヤーだけでした。

| | 以前 | いま |
|---|---|---|
| Subject DNA | 「受験経験なし」を選ぶと**17科目すべて**が出て、そこから必ず1つ以上選ばされていた | S1–S3 を**出題しない**。S0 で完了扱い（`pageApplies()`） |
| Practice DNA | 18領域が財務DD・M&A・IPO 等に偏り、事務所や経理補助の日常業務が無かった。P2/P3 は必須 | **24領域**。日々の作業を先に並べ、P2/P3 にも「とくになし」を許可 |

追加した領域は、事務所のサービス名ではなく**担当者の作業**として読める語にしています
（「記帳代行」ではなく「記帳・仕訳」）。

```
記帳・仕訳 / 証憑突合・資料作成 / 給与・年末調整 / 申告書作成 / 月次巡回・訪問 / 相続・資産税
```

出題しないページの扱いは `pageApplies()` に集約し、ページ番号・進捗の分母・
レイヤーの切れ目・再開位置がすべてそれに従います。また「とくになし」と答えた人に
続きを促さないよう、レイヤーの完了判定は**結果の中身ではなく回答したかどうか**で
行います（`computeResult()` の `answered`）。

### Work Style 4軸

| 軸 | 記号 | 一方の極 | 他方の極 |
|---|---|---|---|
| 視座 | P / B | **精密** ディテール・数値の正確性志向 | **俯瞰** 全体構造・ビジネス文脈志向 |
| 推論 | V / X | **検証** 根拠・基準への当てはめ重視 | **探索** 仮説形成・未知の論点重視 |
| 進め方 | S / A | **構造** 計画・標準化・段取り重視 | **適応** 即応・走りながらの調整重視 |
| 作業様式 | D / C | **深掘** 独立・単独深掘り | **協働** 対話・共同作業 |

4軸の極の組合せで16のアーキタイプが決まります。アーキタイプ本体は**Work Styleのみ**から生成します。

### 同点の軸

軸ごとの合計 s は −8〜+8 で、極は s の符号で決まります。ただし s が 0 になる
（＝どちらの極とも言えない）ことが **1軸あたり 13.6%、4軸のどれかで約 44%** 起きます。
そこを内部で勝手に倒したうえでタイプ名も行動傾向も断定するのは、根拠がありません。

**同点になった軸にだけ、二択を1問出します**（`styleTie` — `src/data.js`）。二択なので
必ずどちらかに決まります。

画面には「同点だから聞いている」という説明を出しません（初めて答える人はそこに疑問を
持たないので、仕組みの説明は雑音になります）。選択肢にも極の名前（検証／探索 など）を
出しません。ラベルが見えると「いつもの自分」ではなく「その言葉に当てはまるほう」を
選ぶ判断になるためです（`npm test` の「二択の文面に極の名前を出さない」で担保）。出るのは Work Style の直後の1ページだけで、たいていは1問です
（4軸すべてが同点になるのは、全部同じ選択肢を押した場合など）。同点が無ければページ自体
出ないので、16問4ページの軽さは変わりません。

二択で決まった軸は s = ±1 として扱うので `pct` は 56 になり、極は本人が選んだものになります
（`resolved: "answer"`）。二択に答えていない同点（古い下書きから結果を作り直した場合）は
`resolved: "fallback"` とし、**その軸から出る行動の行（調べ物は／締切前は／意見が割れたら／結論が出ないときは）を
出しません**（`habitLines()` — `src/scoring.js`）。

> 以前は `|s| <= 2` の軸に「どっちもいける」のタグを出していましたが、左右に伸びるバーの
> 上に置くと「どちらでもない」と読めて破綻するため廃止しました。表示で言い換えるのではなく、
> 同点そのものを回答で解消する形にしています。

### 「経験がなく判断できない」を出さない

**実務経験を前提にする語を設問に入れない**、という一本のルールにしています。以前は
Work Style 16問のうち1問だけ（「細かい突合作業より…」）に N/A の選択肢が付いていましたが、

- 49問のうち1問だけ、という基準の無い状態だった
- **各軸は左2問・右2問で釣り合っている**ので、1問が欠測になるとその軸は残った側へ寄る。
  N/A が付いていたのは 視座 の 俯瞰側の1問だったため、使うと 精密 に偏った
- 受験生・監査アシスタント・経理補助まで対象に広げたところなので、「経験がないなら
  答えられない」という逃げ道を並べるのは方向が逆

という理由で、設問側を誰でも答えられる文言に直して N/A を外しました
（「細かい**数字を合わせているとき**より…」）。`npm test` の「NA を出す設問を持たない」
「Work Style の各軸は左右2問ずつ」で、基準の無い例外が戻らないようにしています。

未回答そのものは引き続き欠測として扱い、0点にはしません。

### 極の意味

極の名前（精密／俯瞰 など）だけでは意味が分かりません。長い説明（`lDesc`/`rDesc`）は
Profile Map の中にありますが、**既定で畳んであり、しかも該当した側の4極しか出ません**。
Work Style のバー・図鑑・16タイプの表では、名前だけを読まされる状態でした。

`lHint`/`rHint`（各8字以内）を持たせ、左右を1行にして出します。

| 軸 | |
|---|---|
| 視座 | 精密＝数値の正確さ ／ 俯瞰＝全体の構造 |
| 推論 | 検証＝根拠と基準 ／ 探索＝仮説から試す |
| 進め方 | 構造＝段取りが先 ／ 適応＝走りながら |
| 作業様式 | 深掘＝一人で深く ／ 協働＝話しながら |

置き場所は2か所だけです。結果画面は各バーの直下に該当軸の1行、図鑑は表の下に4行の凡例。
注記ではなく凡例なので、読み飛ばしても本文の流れは切れません。

### タイプ同士の距離

**相性は言いません。** 出すのは「4軸のうちどれが違うか」という事実だけです。近い＝合う、
ではありませんし、近い／遠いに優劣もありません。相性を言った時点で当たり外れの話になり、
「型に決めつけない」から外れます。

| 場所 | 出すもの |
|---|---|
| 結果画面「ここが1つ違うと」 | 4軸それぞれを1つ裏返すと誰になるか（`neighbors()`）。押すと図鑑のプレビューへ入る |
| 図鑑の先頭「16タイプの位置関係」 | 4×4 の配置（`typeGrid()`）。自分のタイプには枠と「あなた」 |
| 図鑑の各カード | 自分のタイプと比べてどの軸が違うか（`axisDiff()`）。自分のタイプには「あなたのタイプ」 |

**数は出しません。** 「1軸違い」「4軸違い」と数えると 1→4 の段階に見え、近いほうが良いという
順位として読まれます。違う軸の名前を挙げれば同じ軸は言わなくても分かるので、事実としては
それで足ります（`npm test` の「違いを数で言わない」で担保）。

#### 4×4 の並び

たてに 視座×推論、よこに 進め方×作業様式 を割り当て、並び順を「隣り合うものは1文字だけ
変わる」順（P V → P X → B X → B V）にしてあります。その結果、**たて・よこに隣り合うタイプは
必ず軸が1つだけ違い**、左右の端どうし・上下の端どうしも隣になります（4軸の組合せを平面に
開いた形。カルノー図と同じ原理）。32組すべてで成立することを `npm test` で検証しています。

線も矢印も距離の数値も引きません。位置そのものが関係を表すので、近い遠いに優劣を
与えずに済みます。

**表として見えることが要件です。** 罫線はコンテナの背景色 + 1px の `gap` で作り、
見出しには背景色を敷いています。左上の角に たての軸名、その右の帯に よこの軸名、
各行の左と各列の上に極の組（精密 × 検証 など）を置き、列見出しはセルと同じ列・同じ幅に
揃えています。行見出しを行の上に敷いていた版は、見出しと絵と名前が別々のものに見えて
読めませんでした。

セルにはタイプ名を入れます。絵だけだと暗い絵（クモ・モグラ）の動物が判別できないので、
識別は名前が持ち、絵は雰囲気に回します。375px でセル 75px、320px で 61px。
4行すべてが1画面に入ります（375×812 で表の下端 759px）。

図鑑の比較は **`state.result.fromAnswers` が真のときだけ**出します。共有リンクから復元した
結果は他人のものなので、それを基準に16タイプを並べません。

### 名前に前置する修飾語

アーキタイプ名の前に、性格から取った修飾語を1語だけ添えます（例: **まわりを立てる** ナレッジビルダー）。

| 特性 | 70以上 | 30以下 |
|---|---|---|
| 協調性 A | まわりを立てる | 率直な |
| 情動安定性 S | 動じない | 機微に気づく |

- **使うのは協調性と情動安定性の2特性だけ**です。Work Style 4軸のうち3軸は Big Five と
  意味が重なるため（推論=開放性 / 進め方=誠実性 / 作業様式=外向性）、そこから修飾語を採ると
  同じことを二度言うだけになります。視座を含め、残る非重複の特性がこの2つです
- 50 から 20 以上離れているときだけ付けます。**突出がなければ付けません**（全員にラベルを貼らない）
- 両方が突出したら、50 からの差が大きいほうを採ります
- **動物とアーキタイプコード（4文字）は増えません。** `t/{CODE}/` の16ページと og:image は
  そのまま使えます
- 修飾語は名前の一部ではなく「あなたにかかる形容」なので、名前より一段小さい別の行に置きます。
  共有リンク（`#p=` は Work Style のみ）や図鑑プレビューでは素の名前だけになりますが、
  ベース名が常に主役なので別タイプには見えません
- 共有カード（画像）には入れます。本文（テキスト）には入れません

### X への共有

**X へは画像を添付せず、リンクで飛ばします。** リンク先 `/t/{CODE}/` の og:image で
リンクカードに動物が大きく出るので、添付は要りません。

共有ボタンは `<button>` ではなく **`<a href="https://twitter.com/intent/tweet?…" target="_blank">`** です。
`window.open(url, "_blank", "noopener")` のように第3引数（feature 文字列）を渡すと、
ブラウザはタブではなく**ポップアップ**を開こうとし、ポップアップブロックに阻まれて
何も起きません（実測で `window.open` が `null` を返しました）。リンクなら通常のタブ遷移
として必ず開きます。

> **クリックを横取りして `navigator.share()` に回してはいけません。**
> 以前は画像を添付できる端末で `preventDefault()` → 共有シート、としていましたが、
> これだと X ではなく OS の共有シートが開きます。画像の生成が終わる前に押したときだけ
> 横取りが空振りしてリンクとして X が開くため、「何度か押すと X が開く」という挙動に
> なっていました。いまは X ボタンに `onClick` を置いていません
> （`npm test` の「Xボタンはクリックを横取りしない」で担保）。

本文は次のとおりです。

```text
会計人16タイプ、私は「ナレッジビルダー」でした
#会計人プロフィール
（+ URL）
```

### 共有リンクを転送されたとき

共有リンクを開いた人がもう一度「結果リンクをコピー」しても、**数値が落ちないようにしています**。
以前は「自分の回答から出した結果か（`fromAnswers`）」を条件にしていたため、1回転送するだけで
`#p=` が消え、受け取った側は「アーキタイプは合っているのに数値だけ無い」ものを見ていました。
しかも `/t/{CODE}/` は静的ページとして成立してしまうので、壊れているように見えません。
いまは「4軸の数値を持っているか」だけを条件にしています。

`#p=` の付いていない `/t/{CODE}/` に来た人には、図鑑プレビューとは別の文
（「アーキタイプの紹介ページです。個人の結果（4軸の数値）は含まれていません。」）を出します。
どこかでフラグメントが落ちても、他人の結果として読まれないようにするためです。

### 戻る操作（スワイプバック・端末の戻る）

画面を state で切り替える作りなので、そのままでは履歴が1つも積まれません。図鑑で動物を
開いて一覧へ戻る、質問を1ページ戻る、といった当たり前の操作ができず、戻るとサイトごと
離れてしまいます（実測で `history.length` がトップ→図鑑→詳細と辿っても 1 のままでした）。

画面（`screen` / `page` / `preview` / `previewCode` / `previewFromPath`）が変わるたびに
エントリを積み、`popstate` で戻します。

- **`pushState` に URL を渡しません**（第3引数なし＝URL 据え置き）。渡すと `#p=…` が消えて、
  共有リンクから開いた人が戻ったときに4軸の数値を失います。積むのは状態だけです
- `normalizeUrl()` の `replaceState` は `history.state` を引き継ぎます。`null` を渡すと
  戻ったときに画面を復元できません
- 戻して復元するのは**画面の位置だけ**です。回答（`ans` / `ops`）と結果は持ち越すので、
  結果画面から戻っても最後の質問ページに答えが入ったまま戻り、「結果を見る」で復帰できます
- スクロール位置はエントリごとに持ちます。`history.scrollRestoration` は `manual` にし、
  **復元に `requestAnimationFrame` は使いません**（タブが表に出ていないと発火せず、
  戻したはずの位置が先頭のままになります）
- 位置は**画面を離れる瞬間**に控えます（`keepScroll()`）。`history.state` へ書けるのは
  「進むとき」だけで、戻る操作で離れたエントリにはあとから書けないため、そのままだと
  戻ってから進んだときに先頭へ飛びます。**`scroll` イベントも使いません**（描画していない
  タブでは飛ばず、`replaceState` の連打はブラウザに弾かれます）

### リンクカードの画像

| 貼る URL | 出るカード |
|---|---|
| サイトの URL（告知・note） | `assets/og.jpg`（16タイプ一覧・1200×630） |
| 結果の共有リンク `/t/{CODE}/` | `assets/cards/{CODE}.jpg`（そのアーキタイプ・2400×1350） |

`assets/cards/` の16枚は `renderShareCard(null, code)` で書き出した静的カードです
（個人データを持たず、動物・タイプ名・キャッチコピー・特徴・誘い文句だけ）。
`twitter:card` は `summary_large_image`。小さい正方形サムネイル（`summary`）だと

書き出しはブラウザの canvas で行います。開発サーバーで作るとフッターに localhost が
焼き込まれるので、`renderShareCard(null, code, { siteLabel: "…" })` で本番ドメインを

### Instagram

Instagram はリンクカードを持たず、キャプションのリンクも押せません。貼れるのは画像
だけなので、**URL を画像の中に文字として入れた 1:1 カード**を用意しています
（`renderSquareCard()`、1080×1080 @2x）。横長カードと同じ要素を縦に積み、4軸は
4 列ではなく 4 行にしています。

結果画面では **X と並ぶ共有先として独立したボタン**にしています（保存の行に混ぜると
「結果を失わないための保存」と区別がつかないため）。

| | ボタンの文言 | 動き |
|---|---|---|
| スマホ（画像の生成中） | 画像を準備中… | 押せない |
| スマホ（生成後） | Instagram用の画像を共有 | OS の共有シートへ正方形カードを渡す。シートに Instagram が出る |
| デスクトップ・図鑑プレビュー | Instagram用に保存 | 画像を保存し、続けて「Instagramを開く」リンクを出す |

保存で終わらせないのは、**Instagram の Web 版が PC のブラウザから投稿できる**ためです。
保存が成功したときだけ「Instagramを開く」を添えます（失敗したのに次を案内しても
仕方がないので、成功時のみ）。

**`https://www.instagram.com/` ではアプリは開きません。** Instagram はルート URL を
ユニバーサルリンクに登録していないので、iPhone でも Safari で web が開きます。
アプリを開ける手段はカスタムスキーム `instagram://app` だけです。そこで、

- リンクの `href` は web の URL のまま（スキームを `href` に入れると、アプリが無い端末で
  リンクそのものが壊れ、長押しのメニューも無効なアドレスになる）
- 指で触る端末では `onClick` で `instagram://app` を試し、**1.2 秒たってもページが
  見えたままなら** web へ切り替える（アプリへ移ればページは隠れるので何もしない）

としています。判定は `canUseOsShare()` ではなく `isTouchDevice()` です。X のアプリ内
ブラウザのように `navigator.canShare` を持たない環境でも、Instagram アプリ自体は
入っているためです。

**押しても Instagram には直行しません。** Instagram には X の intent にあたる URL が無く、
`instagram://library?AssetPath=…` はカメラロールのファイルパスを、
`instagram-stories://share` はネイティブアプリが用意したペーストボードを要求します。
Graph API での投稿はプロアカウント＋Meta の審査が前提です。Web ページから画像を渡す道は
OS の共有シートしかないので、文言も「〜でシェア」ではなく「画像を共有」にしています
（隣の「Xでシェア」と同じ形だと直行すると読めるため）。

`navigator.share()` を呼ぶのはここ1か所だけです。

**押した瞬間に Instagram が開くわけではありません。** 出るのは OS の共有シートで、
Instagram はそこから利用者が選びます。Web Share API には渡す相手を指定する方法が無く、
これはブラウザ側の仕様です（指定できてしまうと、サイトが任意のアプリを勝手に起動できる）。
そのため、シートを出すときに「共有シートから Instagram を選んでください。」を
その場に出しています。シートを閉じただけ（`AbortError`）のときは案内も引っ込めます。

なお共有シートから Instagram を選ぶと、開くのは**ストーリーズ**の編集画面です
（フィード投稿のコンポーザーではありません）。フィードに出したい場合は保存してから
アプリで投稿してもらう形になります。

実装上の注意:

- `navigator.share()` はユーザー操作の直後にしか呼べません。押してから画像を作って
  `await` すると操作の権利が切れて弾かれるため、**結果を描いた時点で File を先に作り**、
  押されたときは同期的に渡します（`prepareSquareFile`）
- **できるまでボタンを無効にします。** 以前は間に合っていなければ黙って保存に落として
  いたため、押すタイミングで挙動が変わっていました。いまは「押せる＝必ず共有シートが出る」
- 共有シートを閉じただけ（`AbortError`）のときは、勝手に別の共有を始めません
- カードは内容の指紋（コード + 修飾語 + 4軸）が変わったときだけ作り直します。
  性格を足して修飾語が付くと自動で差し替わります
- 4軸は**数値を出さずバーだけ**にしています（縮小すると読めないうえ、点数の顔をしてしまうため）
- 明るい配色のアーキタイプでも白が沈まないよう、背景に暗い膜を一枚かけ、
  バーの溝は暗色にしています。軸のあいだには仕切りを入れます
  （入れないと隣り合う極名が「俯瞰 検証」のようにひと組の対に見えます）
- 画像が未用意のアーキタイプでは、空の額縁を描かずに文字を全幅で組みます

### スコアリング

- **Likert**: とても+2 / やや+1 / どちらとも0 / あまり−1 / まったく−2。逆転項目は符号反転
- **欠測**: 未回答は欠測として平均から除外する。**0点にしない**
- **Personality**: 特性ごとの有効回答平均 m → `round((m+2)/4×100)`。有効回答3問未満の特性は「判定不能」としてレイヤーごと非表示
- **Work Style**: 軸ごと4問を極方向に合計 s（−8..+8）→ `pct = round(50 + 50|s|/8)`。s>0で左極。s=0（同点）は二択の答えで決め、s=±1 として `pct` 56 にする
- **Study**: 各指標1問。内部では `(v+2)/4×100` を持つが、1問ぶんの情報量に見合わないため**表示はスコアではなく3段タグ**（≥75 いまの学習スタイル / 50 ときどき / ≤25 これから試せる）
- **Subject DNA**: 上位3科目を、選ばれた設問（S1 苦にならない / S2 面白い / S3 いまも語れる）のタグで表示。並び順にのみ内部の重み（S1+2 / S2+3 / S3+2）を使い、**数値は表示しない**。S0 で「受験経験なし」だけを選んだ場合は S1–S3 を出題せず、このレイヤーは結果に出ない
- **Practice DNA**: 上位4領域をタグで表示（コア=好き×やりたい、フロンティア=未経験×やりたい、ほかは 好き / やりたい / 経験あり）。並び順にのみ内部の重み（P2+2 / P3順位3・2・1）を使う。**P1（経験）は加点しない**（経験の有無を適性として扱わないため）

実装は [`src/scoring.js`](src/scoring.js) に集約しています。

### アーキタイプ別ページ（`t/{CODE}/`）と SNS カード

結果は URL のハッシュ（`#p=…`）に入れています。ハッシュは HTTP リクエストに含まれず、
X のクローラーは JavaScript も実行しないため、**1枚の `index.html` では結果ごとに
`og:image` を変えられません**。GitHub Pages はクエリ文字列でも配信を切り替えられないので、
変えられるのはパスだけです。そこでアーキタイプ単位で16ページを事前生成しています。

```bash
node scripts/build-archetype-pages.mjs
```

- 各ページは `og:image` にそのアーキタイプのキャラクター画像（720×720）を持ち、`twitter:card` は `summary`。正方形サムネイルとして切り抜かれずに表示されます（`summary_large_image` は 1.91:1 に中央切り抜きされるため使っていません）
- 本体は同じ `src/app.js` を読み込みます。`#p=…` があれば共有された Work Style を復元し、なければそのアーキタイプの紹介として開きます
- 画像パスは `import.meta.url` 基準で解決するため、どの階層のページからでも同じ `src/` が使えます
- 画像が未用意のアーキタイプでは `og:image` を出しません（404 を指すと壊れたカードになるため）
- **`src/data.js` のアーキタイプや画像を変えたら再実行してコミットしてください**

`SITE`（公開URL）は生成スクリプト冒頭の定数です。独自ドメインに移す場合はそこだけ変えます。

### トップのカード（`assets/og.jpg`）

トップは「どのアーキタイプが自分か」を見せたい入口なので、結果ページの正方形カードとは別に
**キャラクターを8体並べた横長カード**（1200×630 / `twitter:card` は `summary_large_image`）を

## デプロイ

`main` ブランチのルートを GitHub Pages がそのまま配信します。CI・環境変数はありません。
唯一の生成物は `t/{CODE}/`（アーキタイプ別ページ）で、これはコミット済みなので

`package.json` は依存パッケージを持たず、`scripts/` の Node スクリプトから
`src/*.js` を ES モジュールとして読むために `"type": "module"` を宣言しているだけです。

## 注意事項

本サービスは心理学研究（IPIP等の公開心理尺度）を参考にした**独自の自己理解コンテンツ**です。妥当性検証済みの心理検査ではありません。

- 心理検査・能力検査・採用・人事評価を目的としたものではありません
- 適職判定・求人推薦・年収予測は行いません
- Work Style 4軸はプロダクト独自の軸であり、確立した心理尺度ではありません
- Study Behavior は各指標1問のため、0–100 のスコアやバーでは出しません。「当てはまる／どちらともいえない／当てはまらない」の3段タグとして表示し、当てはまらない側も欠落ではなく「これから試せる」として置いています
- Subject / Practice DNA も数値では出しません。選択操作の集計であって測定値ではないため、「なぜその科目・領域が挙がったか」（苦にならない／面白い／いまも語れる、コア／フロンティア／経験あり）をタグで示します
- 設問・アーキタイプ名・解説・画像コンセプトはすべてオリジナルです。MBTI® の設問・タイプ名称・4文字コードは使用していません

### 注意書きの出し方

「これが無いと利用者が結果を誤解するか」だけを基準に置き、繰り返しと言い換えは削っています。

| 残す（誤解の実害がある） | 置き場所 |
|---|---|
| 心理検査・採用評価・適職判定ではない | トップと結果の最下部に1文ずつ |
| アーキタイプは Work Style から作るラベルである | 結果ヘッダーのボタン下に1行 |
| 結果は保存されない・閉じると取り出せない | 結果上部の保存行に1行 |
| Personality の高低に良し悪しはない／Study は各指標1問／DNA は点数ではない | 各カードの見出し脇に短く |
| コア=好き×やりたい、フロンティア=未経験×やりたい | Practice DNA の見出し脇（タグを読むのに必要） |

畳んだもの: トップの PRIVACY 詳細（`<details>`）。
削ったもの: 結果下部の再掲パネルの本文（ボタンだけ残す）、各カードの本文リード、保存パネルの長い補足。

画像が未用意のアーキタイプは、キャラクター画像の代わりにアーキタイプの2色（`c`）のグラデーション帯を出し、そこに動物名を大きく表示します。**絵が無くても「自分が何の動物か」は必ず伝わるようにしています**（ここを空にすると、そのアーキタイプの人だけ動物のいないプロフィールになるため）。
